# QuadFC GCS — نسخهٔ وب (همان برنامهٔ پرِیو)

این پوشه، سورسِ دقیقِ همان ایستگاه زمینی وبی است که در پرِیو اجرا می‌شود؛
**کاملاً سازگار با فریمور `quadfc_logger_v7.hex` روی برد** (و همچنین سوئیت اعتبارسنجی v4.0).

## ویژگی‌ها

- **تشخیص خودکار فریمور**: لاگر سخت‌افزاری v7 (CSV) یا سوئیت اعتبارسنجی v4.0 (منویی) — بدون هیچ تنظیم دستی
- **پارس فریم‌های لاگر v7**: فریم‌های `D` هر ۵۰۰ms (۹۴ فیلد)، جمله‌های `N,$GPRMC/$GPGGA` با چک‌سام، خلاصهٔ `#Q` هر ۱۰ ثانیه (۲۲ شمارندهٔ سلامت)
- **تشخیص خودکار بادریت** (پیش‌فرض 9600 8N1 مثل خود فریمور)
- **فریم آسیب‌دیده = رد می‌شود** (هرگز مقادیر را جابجا پارس نمی‌کند — دقت اول از همه)
- ۱۱ تب: نمای کلی، سه‌بعدی، نقشه، سنسورها، GPS، باتری هوشمند (۲S/۳S/۴S)، عیب‌یابی، کالیبراسیون، گیرنده RC، کنسول، رویدادهای فارسی
- **بازپخش لاگ**: همان متن خام PuTTY را بچسبان — حتی با فاصله‌گذاری‌های به‌هم‌ریخته
- **شبیه‌ساز**: بدون سخت‌افزار هم همهٔ تب‌ها زنده می‌شوند
- ⛔ **بدون هیچ خروجی موتوری** — PB6..PB9 همیشه دست‌نخورده

## اجرا

```bash
cd webapp
bun install        # یا: npm install
bun run dev        # یا: npm run dev
```

سپس `http://localhost:3000` را با **Chrome یا Edge دسکتاپ** باز کن
(اتصال سریال از Web Serial API استفاده می‌کند و فقط در این مرورگرها هست).

1. برد را با USB-TTL وصل کن (PA9=TX → RX دانگل، PA10=RX → TX دانگل، GND↔GND)
2. دکمهٔ «اتصال خودکار» را بزن و پورت را انتخاب کن
3. برنامه خودش بادریت را پیدا می‌کند و با `?` از فریمور می‌پرسد کیستی؛
   بنر «QuadFC HC-12 Hardware Logger v7.0» → حالت لاگر v7 قفل می‌شود

> نکته: PuTTY باز باشد پورت را نمی‌گذارد باز شود — اول ببندش.

## ساختار

- `src/lib/qfc/protocol.ts` — پارسر v7 (D/N/#Q + NMEA + رویدادهای هوشمند فارسی)
- `src/lib/qfc/serial.ts` — Web Serial + تشخیص پورت/بادریت
- `src/lib/qfc/engine.ts` — موتور اتصال، شناسایی فریمور، شبیه‌ساز، بازپخش
- `src/lib/qfc/valsuite.ts` — پارسر سوئیت اعتبارسنجی v4.0
- `src/components/qfc/` — رابط کاربری (تب‌ها، ابزارها، نقشه، سه‌بعدی)
